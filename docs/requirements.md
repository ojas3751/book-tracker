# 読書管理アプリ 要件定義書

- 版：0.2（ドラフト）
- 最終更新：2026-10-26
- ステータス：技術構成は未決定

---

## 1. 概要

### 1.1 目的
シリーズ単位で新刊を追える読書管理Webアプリを作る。

既存サービスの著者フォロー型の新刊通知は、興味のない作品まで拾ってしまう。本アプリでは**追う単位をシリーズ（作品）にし、ボタンを押したときだけ対象シリーズの新刊を検索する**。

### 1.2 前提
- 形態：Webアプリ
- 利用者：当面は開発者本人のみ。将来公開する場合に修正しやすい作りにする
- 通知機能：作らない
- デザインと使いやすさを重視する
- 端末：PCとスマホを同じくらい使う想定。どちらでも使いやすい画面にする

## 2. データソース

| ソース | 役割 | 備考 |
|---|---|---|
| 楽天ブックス書籍検索API | メイン | 発売予定の本に強い。利用条件が緩い |
| Google Books API | 補助 | 日本の新刊情報は弱く、遅れがち |
| openBD / NDLサーチ | 補助 | ISBNによる書誌情報の補完 |
| Amazon PA-API | 使わない | アソシエイトの売上実績が利用条件。データ取得だけの利用は想定されていない |

### 2.1 共通方針
- 外部APIはサーバー側からだけ呼ぶ（APIキーを隠す）
- 各ソースを共通のインターフェースで包み、差し替え・追加できるようにする

### 2.2 楽天ブックス書籍検索API
- バージョン：2017-04-04
- エンドポイント：`https://openapi.rakuten.co.jp/services/api/BooksBook/Search/20170404`
- 認証：`applicationId` と `accessKey` が必須
- レート制限：公式に具体的な数値の記載なし。HTTP 429（`too_many_requests`）が返ったら待ってから再試行する。短時間に同一URLへ繰り返しアクセスしない

**主な入力パラメータ**

| パラメータ | 用途 |
|---|---|
| `title` / `author` | シリーズの検索キーワード／著者 |
| `size` | 判型での絞り込み |
| `booksGenreId` | ジャンルでの絞り込み |
| `sort=-releaseDate` | 発売日の新しい順 |
| `outOfStockFlag=1` | 品切れ・予約中も含める |
| `hits` | 1ページの件数（最大30） |

**主な出力項目**：`isbn`、`title`、`subTitle`、`seriesName`、`author`、`titleKana`、`authorKana`、`publisherName`、`salesDate`、`size`、`booksGenreId`、`itemUrl`、`smallImageUrl` / `mediumImageUrl` / `largeImageUrl`

**`size`（判型）**

| 値 | 意味 |
|---|---|
| 0 | すべて（入力時のみ） |
| 1 | 単行本 |
| 2 | 文庫 |
| 3 | 新書 |
| 4 | 全集・双書 |
| 5 | 事・辞典 |
| 6 | 図鑑 |
| 7 | 絵本 |
| 8 | カセット・CD |
| 9 | コミック |
| 10 | 雑誌・その他 |

**主なジャンルID（`booksGenreId`）**

| ジャンル | ID |
|---|---|
| 本（全体） | `001` |
| 漫画（コミック） | `001001` |
| └ 漫画の文庫版 | `001001006` |
| 小説・エッセイ | `001004` |
| ライトノベル | `001017` |
| 文庫 | `001019` |
| 新書 | `001020` |

### 2.3 分類に関する注意
- 小説は単行本で出たあと文庫化されることがあり、同じ作品でも判型とジャンルIDが変わる
- ラノベは大半が文庫だが、Web小説の書籍化などで単行本サイズのものも多い
- 著者で検索すると、コミカライズ版が混ざることがある
- マンガの文庫版も漫画（`001001`）の下に入るため、コミックの絞り込みには `size` ではなくジャンルIDを使う

## 3. 機能要件

### 3.1 本の登録
- タイトル、著者、ISBNで外部APIを検索し、結果から選んで登録する
- 検索画面に「コミックのみ」のチェックボックスを置く（`booksGenreId=001001` で絞る）
- 検索結果のうち登録済みの本には「登録済み」の目印を付け、押すとその本のブックページを開く
- 外部APIで見つからない本（同人誌、ISBNのない古い本など）は、書誌情報を手で入力して登録できる
  - 手で入力した本は、その人だけのデータとして扱い、ほかのユーザーと共有しない
  - 手で入力した本の書誌情報は、ブックページの編集モードで直せる
  - 必須の項目はタイトルと購入状況（購入済みなら媒体と購入場所も）。店頭で見つけてそのまま買ったのか、買うのを保留したのかを記録するため
  - 著者、出版社、発売日、判型、ISBNは任意
  - 表紙の画像は任意でアップロードできる。画像がなければ、タイトルを書いたダミーの表紙を出す
- 登録時に設定できる項目
  - シリーズ（既存を選ぶ／新規に作る／なし）
  - 巻数
  - 新刊を追うかどうか、追う判型（シリーズの設定）
  - 購入状況（購入済みの場合は読書状態、媒体、購入場所も）
  - タグ

### 3.2 本のステータス

| 項目 | 値 | 入力形式 | 備考 |
|---|---|---|---|
| 読書状態 | 積読／読書中／読了 | 選択 | 購入済みのときだけ選べる。それ以外は「未購入」と表示する（値は保存しない） |
| 購入状況 | 購入済み／購入予定／買わない | ラジオボタン | |
| 媒体 | 紙媒体／電子書籍 | ラジオボタン | 購入済みのときだけ表示 |
| 購入場所 | 購入場所タグから1つ | 選択 | 購入済みのときだけ表示 |
| 評価 | 星5つ（0.5刻み） | 選択 | 1〜10の整数で保存（星1つ＝2）。未評価は `null` |
| メモ | | 自由入力 | |

- 1冊につき媒体と購入場所は1つずつ（紙と電子の両方を持つケースは想定しない）
- 購入せずに読んだ本（図書館、無料公開など）は管理の対象にしない
- 購入済みに切り替えたときは、同じシリーズで最後に購入した本の媒体と購入場所を初期値に入れる
- ブックページで、登録時と同じ項目（シリーズ追跡の設定を含む）を変更できる

### 3.3 タグ
- 本ごとに自由なタグを複数付けられる
- 購入場所のタグとして「店頭」「Kindle」「楽天」「Google」を初期データとして用意する（追加・削除可）
- 購入場所のタグと自由なタグは同じテーブルで管理し、種類（`kind`）で区別する

### 3.4 登録済みの本の検索
- テキスト検索（タイトル、著者、シリーズ名）
- タグでの絞り込み（複数選択可。既定はAND、ORに切り替え可）
- 購入状況、媒体、読書状態、シリーズの追跡のオン・オフでの絞り込み
- 本棚はシリーズごとにまとめて表示するため、条件に合う巻が1冊でもあればそのシリーズを表示し、表紙に条件に合う冊数を出す（例：「積読 3」）
- 本棚からシリーズを開いたときは検索条件を引き継ぎ、条件に合う巻だけを表示する。絞り込み中であることを表示し、解除すると全巻を表示する。ほかの画面から開いたときは全巻を表示する

### 3.5 シリーズ

| 項目 | 内容 |
|---|---|
| 表示名 | 自由に編集できる |
| 読み仮名 | 並べ替えに使う。楽天の `titleKana` から自動で入れ、手動で直せる |
| 検索キーワード | 新刊検索に使う。表示名とは別に持つ。`seriesName` やタイトル（巻数などを除いたもの）から自動で入れ、手動で直せる |
| 著者 | 新刊検索に使う |
| 追う判型 | `any`／`tankobon`／`bunko`／`shinsho`／`comic`。最初の1冊の判型とジャンルから自動で入れ、手動で直せる（下記） |
| 追跡 | オン・オフ。既定はオン |

- シリーズ情報は、シリーズを作るときに最初の1冊の書誌情報から初期値を入れる。あとで巻を足しても、手で直した値は上書きしない
- 追う判型の初期値
  1. ジャンルIDが漫画（`001001` 以下）なら `comic`
  2. それ以外は `size` が 1 なら `tankobon`、2 なら `bunko`、3 なら `shinsho`
  3. どれにも当たらなければ `any`
- 本の登録の画面とブックページには判型を表示し、どの判型を追うことになるかがわかるようにする
- 自動で決める方法は、実際に作って触ってから調整する
- 楽天の `seriesName` には、作品のシリーズ名ではなくレーベル名（「○○文庫」など）が入る場合がある。表示名や検索キーワードを `seriesName` とタイトルのどちらから作るかは、実際のデータで確かめてから決める

**シリーズの集計の値（本棚やシリーズページに出す）**：所持している最新巻とその発売日、刊行済みの最新巻、評価の平均、購入予定の冊数、表紙（所持している最新巻のもの）は保存せず、持っている本からその都度計算する

### 3.6 本棚の並べ替え
本棚にはシリーズと、シリーズに入っていない本が混ざって並ぶ。シリーズに入っていない本は、表示名をタイトル、読み仮名を `title_kana`、発売日をその本の発売日として扱う。

| 選択 | 並び順 |
|---|---|
| 発売日順（既定は新しい順） | 所持している最新巻の発売日（新しい順／古い順） |
| A–Z順 | 英字グループ（A–Z） → 日本語グループ（あいうえお順） |
| あいうえお順 | 日本語グループ（あいうえお順） → 英字グループ（A–Z） |

**グループの判定**
1. 表示名の先頭から記号を読み飛ばし、最初の文字で判定する（例：「【推しの子】」は「推」で判定）
2. 全角英字は半角にそろえてから判定する
3. 英字なら英字グループに入れ、表示名で比較する（大文字・小文字は区別しない）
4. それ以外（漢字、かな、数字）は日本語グループに入れ、読み仮名で比較する（例：「86」は「えいてぃしっくす」）

### 3.7 新刊検索

#### 3.7.1 検索の単位
- **シリーズ単位（基本）**：シリーズページの［新刊を検索］ボタンで、そのシリーズだけを検索する
- **全体一括**：
  1. 本棚の［全体一括で新刊を検索］ボタンを押すと確認ポップアップを表示する（対象件数と、時間がかかる旨）
  2. OKなら、追跡中のシリーズを順番にシリーズ単位で検索する
  3. 実行中は進み具合（〇/〇件）と中止ボタンを表示する
  4. 終わったら（中止した場合も）、新刊候補の画面を開く。前からあった未判定の候補も含めてすべて表示し、今回初めて見つかった候補には「NEW」の目印を付ける（3.7.8）
- 検索後、シリーズの `last_checked_at` を更新する

#### 3.7.2 取得
楽天APIを次の条件で呼ぶ。
- `title`：シリーズの検索キーワード
- `author`：シリーズの著者
- `sort=-releaseDate`、`outOfStockFlag=1`
- 追う判型が `comic` の場合は `booksGenreId=001001`

#### 3.7.3 除外
取得結果から次のものを除外する。

| 判定 | 内容 |
|---|---|
| 登録済み | ISBNが自分の本棚の本と一致する |
| 記録済み | ISBNが `release_candidates` にある（状態は問わない）。同じ候補を二重に記録しないための除外で、未判定の候補は引き続き表示する |
| 著者の不一致 | 正規化した著者名に、シリーズの著者が含まれない |
| タイトルの不一致 | 正規化したタイトルにも `seriesName` にも、検索キーワードが含まれない |
| 判型の不一致 | 追う判型と `size` が合わない（`tankobon`＝1、`bunko`＝2、`shinsho`＝3。`any` と `comic` は判定しない。`comic` はジャンルIDで絞る） |

**正規化**
- 全角と半角をそろえる（英数字、記号）
- 空白と記号を取り除く
- 著者名から役割表記（著、イラスト、原作、漫画など）と区切り文字を取り除く

#### 3.7.4 分類

| 分類 | 条件 | 表示 |
|---|---|---|
| 新刊・予約 | 巻数が所持している最大の巻数より大きい。巻数が取れない場合は、発売日が前回の確認日時以降、または所持している本の最新の発売日より後 | 常に表示 |
| 未所持の既刊 | 巻数が所持している最大の巻数以下で、未所持 | 設定でオン・オフ（既定はオフ） |
| 別版 | 所持している巻やほかの候補と巻数が重なる（特装版、限定版、文庫化版など） | ラベルを付けて表示 |

#### 3.7.5 巻数の抽出
- タイトルとサブタイトルから正規表現で抽出する
  - 対応する形式：`第3巻`、`3巻`、`(3)`、`（3）`、末尾の数字
  - 全角数字・漢数字は半角の数字に変換してから判定する
  - 上・中・下、前編・後編は順序の値に置き換える
- 抽出できない場合は `null` にし、発売日で判定する。ブックページで手動で直せる

#### 3.7.6 発売日
- `salesDate` は `YYYY`、`YYYY-MM`、`YYYY-MM-DD` のほか、上旬・中旬・下旬などが付く場合がある
- 比較用の日付に変換して保存し、元の文字列も保存する（表示には元の文字列を使う）
  - 上旬 → 5日、中旬 → 15日、下旬 → 25日、日付なし → 1日（仮の値）

#### 3.7.7 候補への操作
- **本棚に追加**：購入状況の初期値は「購入予定」
- **対象外**：自動の除外をすり抜けた、シリーズと関係ない本に使う。対象外として記録し、以後表示しない。理由（コミカライズ、別作品、別版など）を任意で選べる
- 対象外にした本は、設定の「対象外一覧」で確認できる
- **未判定**：［本棚に追加］も［対象外］もまだしていない候補（`state` が `new`）

#### 3.7.8 候補の表示
- 新刊候補の画面には、全シリーズの未判定の候補を発売日の新しい順に並べる
- シリーズページでは、持っている巻の一覧とは別の枠に、そのシリーズの未判定の候補をまとめて出す（発売日の新しい順）
- **NEW の目印**：そのシリーズの直近の新刊検索で初めて見つかった候補に付ける（`found_at` がシリーズの `last_checked_at` と同じもの）。シリーズ単位の検索でも全体一括でも同じ扱いで、そのシリーズをもう一度検索すると外れる

### 3.8 設定
- 未所持の既刊を新刊検索の結果に表示するか（既定はオフ）
- 対象外一覧：対象外にした本を確認する
  - 表示項目：表紙、タイトル、シリーズ名、理由、対象外にした日
  - 対象外にした日の新しい順に並べる。シリーズで絞り込める
  - ［元に戻す］で新刊候補に戻す（`state` を `new` に戻す）

### 3.9 編集と削除

**編集**
- シリーズページとブックページは、普段は表示だけにする。［編集］を押すと編集モードに切り替わり、［保存］［キャンセル］で戻る
- シリーズページの編集モードではシリーズ情報を、ブックページの編集モードでは登録時と同じ項目を直せる
- 読書状態や評価などのステータスも、ブックページの編集モードで変える。一覧（本棚、シリーズページ）からは直接変えない
- 本を別のシリーズに移すときは、ブックページでシリーズを変える
- ［削除］は誤操作を防ぐため、編集モードの中にだけ置く

**本の削除**
- ブックページの［削除］で、確認してから削除する
- 削除するのは自分の登録データ（`user_books`、`user_book_tags`）だけで、共有の書誌データ（`books`）は残す。ただし手で入力した本は共有していないので、書誌データも削除する
- その本の新刊候補の記録（`release_candidates`）も削除する。削除は「管理をやめる」ことなので、新刊検索でまた候補に出るようにする（関係ない本を出さないようにするのは「対象外」の役割）

**シリーズの削除**
- シリーズページの［削除］を押すと、「登録した本も削除しますか？」と確認する
  - はい：シリーズと、そのシリーズの本をすべて削除する
  - いいえ：シリーズだけを削除し、本は「シリーズなし」に戻す
- どちらの場合も、そのシリーズの新刊候補（対象外にしたものを含む）は削除する

### 3.10 ストアへのリンク
- 自分で使う段階では設置しない（管理に特化し、購入は各サービスのアプリで行う）
- 公開時に設置を検討する。そのため、ISBNと楽天の `itemUrl` は保存しておく

## 4. 画面構成

### 4.1 画面一覧

**呼び方**：シリーズの画面を「シリーズページ」、1冊の画面を「ブックページ」と呼ぶ。シリーズそのものの情報（表示名、読み仮名、検索キーワード、著者、追う判型、追跡）は「シリーズ情報」と呼ぶ。

| 画面 | 主な中身 |
|---|---|
| 本棚（ホーム） | 登録済みの本の一覧（シリーズごとにまとめ、シリーズに入っていない本は1冊ずつ表示）、テキスト検索、絞り込み、並べ替え、［全体一括で新刊を検索］ |
| 本の登録 | 外部APIの検索（「コミックのみ」付き）→ 選ぶ → 登録項目を入力 |
| ブックページ | 書誌情報、ステータスの編集、シリーズ追跡の設定、［＋］ |
| シリーズページ | 所持している巻の一覧、［新刊を検索］、そのシリーズの候補、［＋］ |
| 新刊候補 | 全シリーズの未判定の候補（本棚に追加／対象外） |
| 設定 | 未所持の既刊の表示、タグ（購入場所を含む）の管理、対象外一覧 |

### 4.2 ナビゲーション
- サイドメニューに各画面への入口を置く（本棚、本の登録、新刊候補、設定）
- 「新刊候補」の横には、未判定の候補の件数を出す（例：「新刊候補 3」。0件なら出さない）
- PCでは常に表示する。スマホでは普段は閉じておき、≡ボタンで開く

### 4.3 本の登録の入口
| 入口 | 初期値 |
|---|---|
| サイドメニュー | なし |
| シリーズページの［＋］ | そのシリーズ |
| ブックページの［＋］ | その本のシリーズと、巻数（その本の巻数＋1。巻数が `null` ならシリーズだけ） |

- 登録が終わったら、開く前の画面に戻る

### 4.4 一覧の表示切り替え
- 一覧系の画面はグリッドとリストを切り替えられる
- グリッドは表紙を眺めるため、リストは情報を見比べるため（刊行のペースなど）に使う。そのため、表示する情報は両者で変えてよい
- 最後に選んだ表示を画面ごとに覚えておく。初めて開いたときの表示はグリッドにする
- スマホのリストは幅が狭いため、PCより項目を減らす

| 画面 | グリッド | リスト（PC） | リスト（スマホ） |
|---|---|---|---|
| 本棚 | 表紙、巻数（例：「5/7」）、所持している最新巻の発売日 | タイトル、著者、巻数、発売日、購入状況、評価、追跡のオン・オフ、前回の確認日、未判定の候補の件数 | タイトル（追跡中ならアイコンを添える）、巻数、発売日、購入状況、評価 |
| シリーズページ | 巻順に並べた表紙と巻数。未購入の巻は薄く表示し、「未購入」と記載する | 巻数、発売日、購入状況 | PCと同じ |
| 新刊候補 | 表紙、タイトル、分類のラベル（新刊・既刊・別版） | 発売日、シリーズ名、タイトル、分類、［本棚に追加］［対象外］ | シリーズ名と巻数、発売日、分類、［本棚に追加］［対象外］（ボタンはアイコンで表示） |

- リストでは未購入の巻を薄くせず、色付きのマーカーや文字色で未購入とわかるようにする
- 「所持している」は購入状況が「購入済み」のものを指す
- **刊行済みの最新巻**：所持している巻と新刊候補（対象外にしたものと別版を除く）のうち、発売日が今日以前のものの最大の巻数。新刊検索をまだしていないシリーズでは不明とする

**本棚のシリーズの項目**

| 項目 | シリーズの行 | シリーズに入っていない本の行 |
|---|---|---|
| タイトル | シリーズの表示名 | 本のタイトル |
| 巻数 | 所持している最新巻／刊行済みの最新巻（例：「5/7」、不明なら「5/–」） | なし |
| 発売日 | 所持している最新巻の発売日 | 本の発売日 |
| 購入状況 | 購入予定の冊数（例：「予定2冊」）。なければ空欄 | 本の購入状況 |
| 評価 | 評価が付いている巻の平均。0.5刻みには丸めず、星の数を小数第1位まで出す（例：「★3.8」。第2位は四捨五入） | 本の評価 |
| 追跡・前回の確認日・候補の件数 | シリーズの値 | なし |

- 読書状態とタグは1冊ごとの項目なので、本棚のリストには出さず、絞り込みで使う

### 4.5 本棚で見つからないとき
- テキスト検索で1件も出なかった場合、「ブラウザで検索」のリンクを表示する
- 検索語を引き継いで、Googleの検索結果を新しいタブで開く

### 4.6 一覧の読み込み
- 件数を決め打ちにせず、画面何枚分かで決める（端末の大きさによらず同じように動かすため）
  - 最初に画面2枚分を読み込む
  - まだ見ていない分が画面1枚分を切ったら、次の2枚分を読み込む
  - グリッドは段単位で数える
- 例（Pixel 9）：リストは1画面7件 → 最初に14件、以後14件ずつ。グリッドは3列×4段 → 最初に24冊、以後24冊ずつ
- 表紙の画像は、見える直前に読み込む
- 本の登録の検索結果は、楽天APIから1回で30件を取得し、表示だけを上の方法で増やす

### 4.7 ページの開き方
- シリーズページとブックページは一覧の上に重ねて開き、一覧の画面は裏に残す（一覧のスクロール位置を保つため）
- 戻るボタン・戻るジェスチャーで、重ねたページを閉じる
- ページを重ねて開いている間、裏の一覧はスクロールしない
- 重ねるのは2枚まで（シリーズページ → ブックページ）
- 重ね方（全画面で重ねる／PCは横のパネル・スマホはボトムシート）はモックで比べて決める

### 4.8 キャッシュ
- 楽天APIの検索結果は、同じ検索語なら短い間だけメモリに残す。新刊検索ではキャッシュを使わず、毎回問い合わせる（発売日の更新や予約の開始を拾うため）
- 本棚の一覧は読み込んだ分をメモリに残す。シリーズページやブックページで編集したら、一覧の表示もその場で直す
- 表紙の画像はブラウザのキャッシュに任せ、自分では保存しない

## 5. データモデル（案）

```
books              : id (PK), isbn (null可, 一意), title, sub_title, series_name, authors,
                     title_kana, author_kana, publisher,
                     sales_date_raw, sales_date, size, genre_id,
                     cover_url, item_url,
                     source (rakuten/google/openbd/ndl/manual),
                     owner_user_id (手で入力した本だけ。APIから取った本は null)

series             : id (PK), user_id, name, name_kana, search_keyword, author_key,
                     preferred_format (any/tankobon/bunko/shinsho/comic),
                     tracking (bool), last_checked_at

user_books         : user_id, book_id, series_id, volume,
                     read_status (tsundoku/reading/finished, null可),
                     purchase_status (purchased/planned/skip),
                     format (paper/ebook, null可),
                     store_tag_id (null可),
                     rating (1〜10, null可), memo, added_at

tags               : id (PK), user_id, name, kind (store/general), sort_order

user_book_tags     : user_id, book_id, tag_id

release_candidates : user_id, series_id, book_id, found_at,
                     category (new/backlist/variant),
                     state (new/added/dismissed),
                     dismiss_reason, dismissed_at

settings           : user_id, show_missing_backlist (bool, 既定 false)
```

- 書誌データ（`books`）はユーザー間で共有、それ以外はユーザー別のデータとして分ける。ただし手で入力した本（`source` が `manual`）は、`owner_user_id` の人だけのデータにする
- 本は `id` で見分ける。ISBNのない本（手で入力した本）があるため、ISBNは主キーにしない。ISBNがある本は、ISBNで重複を防ぐ
- 新刊候補はAPIから取るので、必ずISBNがある
- 全テーブルに `user_id` を持たせ、当面は固定のIDを入れる
- `read_status`、`format`、`store_tag_id` は購入済みのときだけ値を入れる

## 6. 非機能要件・公開を見据えた方針

### 6.1 拡張性
- 認証を追加するだけでマルチユーザーにできる作りにする
- 外部APIのソースを差し替え・追加できるようにする
- サーバー側の処理の入口をまとめておく（後から共通処理を追加しやすくするため）

### 6.2 個人情報・ログ
- 保持する個人情報は最小限にする。公開時に認証を入れても、メールアドレス程度にとどめる
- アクセスログは記録しない。ログ用のコードやテーブルも置かない
- 退会時はメールアドレスと登録データをすべて削除する
- 捜査機関の要請や令状には、その時点で保有している範囲で対応する

### 6.3 公開時に必要なもの
- プライバシーポリシー
  - 利用目的、取得する情報、利用する外部サービス
  - アクセスログは「運営者としては記録・保存しない」と記載する
  - 「法令に基づく場合を除き、第三者に提供しない」と記載する
- 利用規約（新刊情報の正確さを保証しない、などの免責）
- 退会機能

### 6.4 公開後の検討事項
- ストアへのリンクを設置する
- リンクのクリック数を見て、Amazonアソシエイトへの登録を判断する（登録から180日以内に売上3件が必要）
- アソシエイトに登録したら、広告であることの表示を行う（景品表示法のステマ規制、Amazonの規約）
- 通知機能を作る場合、アフィリエイトリンクを含むメールは特定電子メール法の対象になりうる
